# 游戏内容创建与本机 Python 分流

“做一个召唤权杖”等新物品需求自动加载 `items` 和 `content`；召唤行为同时加载 `entities`。调用 `generate_content_package` 生成模型与游戏内脚本，通过既有校验、候选修复、发布和激活流程应用。需要编写代码不等于需要本机 Python。

更新物品、内容包、本机能力说明与内容生成提示。游戏内容创建没有要求本机操作时，误加载 `host` 或直接调用 `python_execute`／`python_install_packages` 会得到 `GAME_CONTENT_TOOL_REQUIRED`、`NOT_STARTED` 和应使用的游戏工具说明。错误返回原工具调用，模型继续同一任务；不插入新的玩家提示词、不创建本机审批或下载 Python。

明确提出“用 Python 生成模型数据”“在电脑打开记事本”等本机请求仍可加载本机能力，并保留逐操作确认、权限和真实执行回执。否定语句“不用 Python”“不需要 Python”不会因包含关键词而触发本机加载。这里改变新请求的路由，不终止其他任务中已经授权的本机操作。

测试包含物品请求的正确能力加载、否定语句、明确本机请求保留，以及隔离游戏内的受控流式工具循环：故意误选本机能力和 Python 后，读取具体失败结果，继续读取真实建模契约并验证模型，检查无本机确认且没有新增玩家消息。此协议测试不调用付费模型，也不冒称已生成并验证完整召唤玩法。
