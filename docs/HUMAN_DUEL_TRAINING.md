# 真人与神经网络对练

专用隔离单人实例通过 `-Dmineagent.humanDuel=true` 启用。不要把该参数加入日常实例：对练世界会创建竞技场、设置规则并替换对练角色的装备。启动工具必须创建独立游戏目录及新世界，不能复制生产存档、配置或账户凭据。

进入后点击聊天中的「准备 / 下一场」，或输入 `/ai duel ready`。每场五秒倒计时；双方生存模式、满血满饥饿、无附魔钻石剑及铁套，无盾牌、药水和 Boost。玩家自行操作，系统不会接管玩家输入。原生碰撞、冷却、伤害、耐久和饥饿规则生效。

共五场，每场最多 180 秒；死亡立即撤销 AI 攻击许可和身体控制，下一 Tick 保存结果。超时判平局。下一场必须再次准备；死亡后先原生重生。`/ai duel stop` 终止整个批次，断线、离开竞技场、维度变化和保存错误也会停止。停止不自动重开；部分数据保留，不算完整五场。

五场固定使用当前随包预训练动作代价网络，关闭在线权重更新但独立记录样本。此网络参与本地合法动作的选择，仍结合 Java 感知、导航、装备和战斗执行逻辑，不是端到端玩家模型。

数据在隔离游戏目录 `human-duel/<批次 ID>/series.json`。记录场次 ID、初始及结束权重散列、装备、双方实际伤害与有效命中、生命值、运动和视角轨迹、原生动作结果样本。每五秒保存进行中轨迹，每场结束原子保存完整结果。瞬时退出仍可能损失最近尚未写盘数据；不把缺失记录补造成真实对战。

训练入口：`python scripts/local-policy/finetune.py --run <隔离启动目录> --output <候选模型.json>`。启动目录需要包含真实 `process.json`（`mode=human_duel`、源码提交、可执行 JAR SHA-256）及 `jvm.args`。如初始模型不同，用 `--initial` 指定本批记录的模型。

导入只接受完整五场、固定权重、独立场次和真实人机来源。以完整场次划分训练和留出数据，不把相邻 Tick 随机分到两边。候选文件独立保存；拟合损失下降不代表真人胜率提升，需后续冻结权重对战评测，不能据此直接替换默认权重。

`-Dmineagent.humanDuelFixture=true` 仅供自动生命周期测试：自动化数据明确标为 `FIXTURE_ONLY`，训练导入器拒绝它，绝不能算作用户参加的五场。
