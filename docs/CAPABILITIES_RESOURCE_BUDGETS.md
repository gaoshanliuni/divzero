执行预算不能丢弃尚未分发的普通事件，先注册的脚本不能持续占据所有时间；单个脚本异常不能使无关脚本失效。需要即时返回决定的原生拦截事件保留明确的同步执行契约，异步任务由调度器推进，不能把世界 API 放到任意后台线程。

生成包仍须以禁用的候选状态完成签名、依赖、脚本及兼容性检查。只有持久化发布确定完成，才能执行自动生命周期步骤。HOT_RUNTIME/允许的热重载可进入运行；WORLD_REOPEN/BOOT_EXTENSION 只能登记待下次打开或启动，不能擅自重启。手动审批和目录/版本级启用入口保留。

方块实体创建不等于允许覆盖已有容器，碰撞策略不等于取消对真实玩家的保护，授权上传不等于开放服务器文件系统。每条路径都保留操作 ID、版本、权限撤销检查和实际回执。

## 脚本调度契约

普通广播 `fire` 按脚本保存回调队列，每次只执行一个回调后轮转；定时器与普通事件在每个脚本中交替，跨 Tick 保留未执行工作。`tick`、`server.tick`、`client.tick` 属于最新状态通知，积压时合并为最新值；普通事件不合并。队列不足时整次广播返回 `SCRIPT_QUEUE_PRESSURE_NOT_ENQUEUED`，不产生半次广播，调用方可等资源恢复再提交。取消、失权、卸载或换版本会清理旧版本的待执行回调。

即时交互、决策、生命周期及持久事件消费者继续使用 `fireTo`/`fireConsumer` 等同步接口，不能把必须立刻给原生事件的返回值拖到以后。一次同步事件共享执行期限；脚本超时只隔离当前作用域，不终止其它脚本。Java 主机调用返回后也检查实际耗时，但不能中断已经进入的任意 Java 阻塞调用；长任务应拆成合作式步骤，不能在服务器线程阻塞等待。

`resources.scripts.*` 设置公开调度时间、每 Tick 回调数量和待处理回调预算；包、缓存模块、处理器、定时器、跟踪资源数量改为告警阈值，超阈值不会禁止新的持久内容。预算更新不清空积压任务。资源观察返回实际耗时、待执行量、压力次数及软预算告警。

脚本可用 `off(event, callback)` 移除后续订阅、`cancelSchedule(id)` 取消尚未开始的定时器、`releaseResource(resource)` 关闭并释放已跟踪资源、`unloadModule(name)` 释放非入口模块的缓存（不撤销已有副作用或其它代码保存的引用）。`on` 返回注册函数，`schedule` 返回定时器 ID；按 `schedule(1, nextStep)` 分片的长任务沿用同一权限和服务器线程。已接受的事件快照不因随后移除订阅而被悄悄丢弃。
