# 存档接入统一到 /ai accept

截图中的提示来自世界服务启动前的身份保护层。此前客户端 `/ai accept` 仅请求签名面板，而服务端在身份尚未接入时拒绝该面板请求；服务也只在进图启动事件中初始化。普通世界启用已统一，但这条更早的接入分支仍会卡住并反复提示。

现在客户端的 `/ai accept` 直接进入服务端接入流程。确认当前玩家和世界权限后，完成存档身份接入、后台启动 Worker、初始化世界服务，并在同一连接刷新启用状态、命令树和工作区。收到当前签名启用快照后客户端完成信任确认；重复接受保持已有会话，较新的禁用或接受意图优先。

界面只显示统一的“是否为你在这个世界中启用 DivZero？”及“一键启用 / 禁用”，身份提示不再自动发送。身份未就绪时使用同一客户端提示样式，按钮绑定当前连接；重复状态查询不刷屏。未启动服务前的“禁用”也按存档和玩家保存，并在接入后转入正式世界选择。旧 `/ai identity` 仍可用于诊断和明确迁移，但不是普通使用的必经步骤。已有旧式选择也可由 `/ai accept` 在当前连接激活，不要求重新进入世界。

## 存档数据处理

- 已绑定且有效的存档直接沿用，不重新生成世界 ID。
- 同一数据根内移动了存档且原路径已不存在时，保留原身份、AI 和作用域。
- 有完整锚点且本机数据库内已有该作用域数据、没有其他冲突绑定时，可以接回该作用域。
- 复制的新地图、损坏或不能明确对应的身份默认建立独立记录，旧记录和原锚点备份保留，不按世界名字猜测或合并其他世界。原记录保留不等于自动恢复到这份新副本。
- 文件正在被另一实例占用、文件不可写、权限不足等实际错误仍会明确返回；不会通过删库或强制解除文件锁假装成功。

存档级接入仍要求世界所有者或管理员；普通联机玩家可以在房主接入后完成自己的启用，也可等待正在进行的房主接入。个人启用不授予 OP 或其他玩家的管理权限。断线、关闭服务器或较新意图会阻止过期启用回调作用到新会话。
