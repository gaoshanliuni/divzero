# 世界启用聊天流程

首次进入世界或服务器时，DivZero 在原生聊天中显示“启用 / 禁用”，不再自动打开设置页或要求先输入 `/ai accept`。按 T 点击即可。F2 与设置中的“此世界启用设置”、`/divzero_setup` 都可重新选择。内置工作区仍使用 LDLib2 的 MC 主题。

启用按钮校验当前连接、玩家、世界、配置实例和签名身份；服务端再次检查当前 ServerPlayer 和一次性连接令牌。持久化成功后立即更新运行中的权限状态、命令树、签名面板快照、工作区会话与 HUD 恢复握手。无需退出世界或全局 reload。按钮同时明确确认所显示的服务器身份；指纹变化会提示核对。

选择按世界 UUID 和玩家 UUID 保存。配置数据库是实例共享的，因此键包含世界 UUID，不能只用玩家 UUID 或旧的全局 `runtime.initialized`。升级后的既有世界也需第一次点击确认；旧授权内容保留，但旧全局初始化标志不替代当前世界的选择。禁用后不会在以后进入这个世界时反复询问，也不影响其他玩家的选择。

禁用会立即阻止本人新的模组操作，撤销相关权限租约、工作区会话、对话和身体接管，移除本机动态 HUD；保留已建造的世界内容和持久数据。启用恢复现有权限，不写入权限授予清单，不提供 OP，不替代电脑操作的逐次本机确认。普通玩家仍受服务器权限和 AI 所有权限制。旧 `/ai accept` 保留为服务端启用兼容入口，客户端尚未确认的身份仍须点聊天按钮。

旧流程的问题是服务端授权、客户端信任和当前连接刷新分离，`/ai accept` 只写配置并发送快照，没有完成统一启用，也没有重新发送命令树。本次使用一条完整的启用流程更新两端状态。

验证：新增世界/玩家隔离、重开后持久化、禁用 OP 与普通玩家、权限租约失效及不扩权测试。隔离 Native fixture 从首次聊天按钮开始，不预置信任、不发送 `/ai accept`，检查禁用、旧按钮拒绝、同一连接启用后创建 AI 与新建工作区对话，再重启检查选择保持。构建和 Native 结果在实际运行后补记；不以测试代码存在冒称通过。

存档身份冲突（如复制世界导致身份待处理）仍由已有身份恢复流程处理；它和正常首次启用是不同情况。
