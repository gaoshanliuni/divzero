# 工作模式、本地战斗与真人托管 · 1.0.21

1.0.21 候选采用网络协议 **11**，客户端和服务端需使用同一候选版本。实现与下表隔离验收已经完成，安装包正在进行最后的构建校验；没有自动创建新 Release，也没有覆盖生产实例。已发布的 1.0.20 仍使用协议 10。

## 使用入口

F2 → AI 玩家 → 行为模式，或右键 AI → 行为模式。两处共用 LDLib2 的 MC 主题编辑器，内置面板不依赖 KubeJS。执行身体默认是 AI 自己；选择“接管我的身体”或明确通过对话要求接管本人，才启动真人输入适配器。

![F2 工作与战斗设置](images/behavior-workspace.png)

![AI 专属面板](images/behavior-agent-profile.png)

主工作、战斗方式、交战规则分别保存。“只改战斗规则”保留工作 ID、进度、目标、区域和未修改的排除规则；“切换主工作”替换对应身体的旧工作。

| 设置 | 可选行为 |
| --- | --- |
| 主工作 | 待命、自由活动、跟随、巡逻、警戒、农务、钓鱼、战斗 |
| 战斗方式 | 自动、近战跑打、近战连击控距、远程控距、守住阵地、脱离交战 |
| 交战规则 | 不攻击、只自卫、保护对象、清理防区、只攻击指定对象 |

可以直接说“继续种田，遇到怪就跑打，打完接着种”“打架参考 combo、W-tap、S-tap 控距”。明确且有权限的参数直接执行，条件不足会返回原因。“跟着我”“停下，什么也别做”有本地即时执行和实际回执，不依赖 Provider 可用性。

## 本地战斗循环

模型理解目标，本地持续观察、选敌、导航、装备和行动。常规循环、即时防御、短退和突围不等待下一次模型回答。

- 读取原生运行中的近战/远程 Goal 冷却与范围、当前目标、速度及变化、Ravager 硬直/咆哮、爬行者引信与实体伤害范围。未适配的限制标为未知。受伤动画、伤害保护和击退分别处理，不当成“不能反击”。
- 所有附近相关威胁和已飞出的弹体参与风险判断，不只保留最近的几个敌人。自动选敌默认排除玩家、友军、有主宠物和排除名单。
- 近战按真实装备距离、冷却和可用退路出手，命中后短退或侧移；根据实际命中、击退与敌方行为继续调整。
- “近战连击控距”参考 combo / W-tap / S-tap：接近时使用原生疾跑，击后释放并重新衔接，短退后在攻击边缘等待；只有观察到实际击退才跟进相应机会。不增加攻击速度、攻击范围、击退量或生命值。
- 持续处于原生近战范围并受到真实伤害时，优先疾跑脱离，再恢复进攻。退路结合平台边缘、可落脚区域、后续出口、可返回性、敌群和当前生命值；没有低风险路线时，允许以原生攻击和一定受击代价创造突破口，避免被逼入致命落差、未知落点或死路。
- 战术路线复用同一套通行判定与实际步骤执行器，执行时继续复核；不把每个短路点重新交给普通寻路的重试计时器。当前路点可行时保持，出现障碍、危险或明显目标变化再改，减少左右反复选路。
- 真人复合动作每个游戏 Tick 只更新一次瞄准方向，移动中的瞄准、潜行与手部动作一起处理。接近路点时保持前方朝向，避免越过路点后一帧反转。
- 盾牌、弓箭、食物使用原版流程。保留实际格挡方向、蓄力、重力弹道、饱食度、耐久和库存消耗，不直接回血。

## 工作、打断与恢复

农务先确认成熟度、种子和真实产物容量，预约工作点，到位后重检，原生收获/补种并接近实际掉落拾取。种子半栈不等于能装小麦；背包满时保留作物，腾出空间后继续。多个 AI 通过预约避免争抢同一工作对象。

钓鱼使用安全站位与原生鱼竿，确认自己的钓钩，读取实际咬钩，再收竿和核对拾取。不会按固定等待时间生成渔获。

遇敌保留原工作与进度，完成防御后重新检查再继续。临时任务可保存恢复关系；期间明确修改的战斗规则会保留到恢复后的工作。有限工作保持 COMPLETED 记录，并进入保留交战设置的独立待命；明确停止会连待命一起结束，不自动重新开战。

重启保存任务定义、区域、进度和恢复关系，重新观察后再恢复；不重放旧攻击、种植或收竿。未知副作用先核对。寻路失败、区块未加载、暂时拥堵及等待资源分别反馈，阻塞拾取路线等待环境变化再尝试。

## 真人托管与退出

- 进入托管释放鼠标。T、F2、切窗和最小化均不中断；普通聊天保持排队语义。
- HUD 提供暂停/继续、退出、追加命令。按钮松开时触发。
- 聊天、F2 和其他界面内的 Esc 只处理当前界面。回到游戏画面后，**600ms 内两次独立按下 Esc** 才退出；第一次提示，长按重复不计，打开界面、切窗或新会话会清空前次按键。
- 退出按钮仍可单击退出。死亡、断线、世界或权限变化终止托管，暂停中的会话也会终止。
- 新行为指令与退出作废旧模型身体权限。明确“什么也别做”同时取消同一玩家/AI 的旧工具请求与排队消息；旧回复不能重新接管或恢复已停止工作。

### 修复与保留的失败

所有失败日志、截图和回执保留在隔离验收目录；没有用修改期望来冒充已完成的世界效果。

| 问题 | 处理 |
| --- | --- |
| 首次 F2 测试只启用了服务端，客户端信任未确认 | 测试改走真实签名启用流程，产品保留信任检查。 |
| 测试窗口失焦时点击继续未生效 | 保留按钮防失焦规则，测试先确认焦点并等待服务端回执。 |
| 腾出的背包格被初始化遗留的野花占满 | 读取实际保存库存确认原因，清理测试残留后重测；产品按真实容量等待。 |
| 停止移动也取消举盾；弓/盾抢占残留旧使用动作 | 分离停止移动与取消手部动作，按子操作取消旧原生使用，重测格挡、移动目标射击和食物消耗。 |
| 进食安全判断一直使用完整耗时 | 改用实际剩余使用时间，完成真实食物消耗。 |
| 被僵尸逼落平台 | 复用已检查路线、提高边缘与不可返回落差代价、允许有限受击突破，并通过墙边回归。 |
| 脱离测试硬编码后退 3 米；开阔场景并未形成持续接触 | 改用真实疾跑位移与原生范围清空；使用背后有墙、侧面有出口的实际受击场景。 |
| 真人连击把短退当作长距离撤离 | 独立短控距评分并允许一步调整，复验实际疾跑命中、连续命中与后退。 |
| 旧 Esc 在聊天/F2 中也结束托管 | 按最新要求改为界面内仅处理界面、游戏画面双击退出，纯状态机与实机均验。 |

## 扩展与适用范围

保留 `inspect_behavior`、`set_behavior_mode`、`set_combat_policy`、`control_behavior` 及原技能工具；Java 的作物、武器、钓具与战斗状态适配入口、脚本启动/查询/策略/控制接口继续可用。F2 内置 UI 直接使用 LDLib2；AI 动态界面仍由 KubeJS 构建和绑定。

已验收上述原版生物、装备和场景，不等于所有第三方武器、生物、服务器规则及任意地形已适配。风险估计持续依据当前观察修正，不保证任意数量、装备或地形下无伤获胜；没有增加 AI 创建数量的产品硬上限。

参考 [TouhouLittleMaid-26.1](https://github.com/TouhouLittleMaid/TouhouLittleMaid-26.1) 的任务拆分与通行组织，独立实现，未复制其资源、无重力箭、额外距离或直接回血。界面与建筑迁移见 [迁移说明](NATIVE_UI_MIGRATION_STATUS.md)，安装依赖见 [安装说明](NATIVE_INSTALLATION.md)。
