### 响应流程与模型设置修复

- 历史摘要与执行过程摘要改为后台并发，主回复使用已有有效上下文继续处理。摘要失败或晚到不再中断主回复。
- 摘要输入仅包含模型正文。工具参数、执行结果和思考文本保留在完整归档中；操作 ID、版本、失败、未知结果与未验证状态由本地结构化记录保留，旧归档可沿连接继续回查。
- 方块搜索默认每页从 64 提高到 1024 个命中，可选 1–4096；方块区域观察默认提高到 16384 格／1024 段。每 Tick 仍最多处理 4096 格，保留已加载区块限制和完整分页游标。
- 修复原生命令零匹配目标、条件不成立时等待约 10 秒的问题。执行队列已结束但没有结果时立即返回明确的无结果状态；未知写入不会被盲目重放。
- 建筑参数错误提供字段路径、期望值与实际问题，JSON 语法错误提供行列；碰撞和状态冲突提供坐标、相关实体或期望／当前方块状态。
- 修复自定义模型输入被模型列表刷新影响的问题，允许保存列表外模型 ID。不同 AI 可独立保存模型选择，全局聊天模型不再覆盖 AI 的显式选择；继续共用现有 API 地址和 Key。

### 验证与安装

两个 Python 构建版本均通过项目测试与打包检查；最终无 Python 包通过隔离世界实机回归。空目标和条件不成立的命令分别为 68 ms、31 ms，正常命令为 51 ms；1296 个扫描结果按 1024＋272 返回，6480 格区域观察一页读完。历史摘要与执行摘要均验证了“摘要仍被阻塞时，主回复已经完成”。两名 AI 的不同列表外模型 ID、具体字段错误和实际碰撞位置也已验证。

以上模型调度验证使用本地受控接口，不代表真实模型服务的端到端耗时。完整范围见[响应优化验收记录](../RESPONSE_LATENCY.md)。

主模组提供 **无 Python** 与 **内置完整 Python** 两种附件，二选一，不能同时安装。内置版包含解释器、标准库、必要 DLL、requests、Pillow、NumPy、colorama 及固定依赖和许可证，首次使用在本地离线解压；无 Python 版明确不支持 Python。两版均使用 Java 管理维护流程。

升级时关闭游戏，备份旧主 JAR 后换入所选版本；保留现有存档、配置与学习权重。依赖继续以独立附件提供，不再发行 MCEF 或 WebGUI 运行包。
