# DivZero 发布流程

[安装与版本](BUILD_JAR.md) · [功能说明](FEATURES.md) · [技术说明](SOURCE_SNAPSHOT.md)

公开 main 包含审核后的源码快照、玩家文档、截图和构建流程。公开仓库保持独立 Git 提交记录，以明确的源码提交和构建产物对应每次发布。

## 发布步骤

1. **选定源码**：确定最新已完成的提交和允许公开的文件清单。
2. **整理快照**：导出生产源码、构建文件、选定测试和公开文档。
3. **审查内容**：检查凭据、个人信息、配置、存档、日志及二进制资源的分发范围。
4. **更新功能文档**：介绍当前功能、实际使用入口和适用范围；直接命令优先，共有功能并列说明原生面板与 F2 入口。
5. **更新截图**：选择实际游戏画面，检查画面和元数据，记录 SHA-256 与场景说明。
6. **提交 main**：在公开 main 上提交经审查的变更。
7. **构建发布**：使用该提交的版本号编译、测试和打包，核对附件后公开开发预发布。
8. **复核下载**：确认标签、源码提交、JAR 元数据、Release 标题、校验值和下载入口一致。

## 审查清单

- [ ] 源码提交、版本号和公开文件清单已确定。
- [ ] 已检查源码、文档、截图、配置样例及 JAR 内容中的凭据和个人信息。
- [ ] 文件清单仅包含本次批准的源码、文档和资源。
- [ ] 配置样例使用占位值。
- [ ] 第三方许可、固定来源和对应源码入口完整。
- [ ] README、功能说明、命令示例与实际代码一致。
- [ ] API URL、Key、模型选择等共有功能同时列出原生与 F2 入口。
- [ ] 截图来自真实运行画面，附有场景与原图校验。
- [ ] 已核对 Minecraft、NeoForge、Java、网络协议和依赖版本。
- [ ] 已完成公开源码构建与测试。
- [ ] Release 附件与对应源码提交匹配。

## 自动开发预发布

[Build JAR](../.github/workflows/build-jar.yml) 对 main 的成功构建发布独立 Pre-release。版本采用已提交的 mod_version，写入主 JAR 元数据、文件名和 Release 标题；历史 SNAPSHOT 提交才采用 UTC 日期和公开提交序号。

附件为主模组、WebGUI 和四个平台的 MCEF 运行 JAR。每位玩家安装其中三份；校验值、许可证和固定源码入口列在 Release 正文。

发布 job 使用同次构建的验证产物，依次完成 draft、上传、附件核验和公开。标签为 Mod 版本；提交和运行身份记录在正文/构建审计中，已发布标签与附件保持可追溯。

构建 job 只读，发布 job 使用临时 `GITHUB_TOKEN`。开发预发布与稳定版分别管理；稳定版使用维护者确认的版本与验收范围。

## 当前命名与不可变边界

Tag和发布标题直接使用Mod版本（当前 `1.0.4`）；主模组文件名为 `DivZero-mineagent-1.0.4.jar`。构建仍由main上的Actions执行，不把本地JAR上传冒充Actions产物。保留源码绑定、附件hash和发布前后校验；不强制移动既有Tag。同一源码/变体可核对重跑，不同源码不能覆盖同一个已发布版本。
