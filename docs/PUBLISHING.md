# DivZero 公开发布说明

DivZero 采用“私密开发、按版本公开源码快照”的方式维护。本文件说明源码快照与正式稳定版的人工检查流程。已配置公开源码的自动构建与开发预发布，见 [BUILD_JAR.md](BUILD_JAR.md)；**不会自动同步私密开发仓库**。

## 仓库职责

- **私密开发仓库**：日常开发、实验、测试和完整开发历史。
- **本公开仓库**：经维护者确认公开的源码快照、项目文档、版本说明和下载入口。

本仓库保持独立的 Git 历史，不作为私密仓库的镜像。公开源码仅在维护者主动发布版本时更新；README、问题反馈模板等公开文档可以单独维护。

## 一次发布的流程

1. **确定版本**：在私密开发环境中选择确切的提交或标签，确定公开版本号与允许发布的文件清单。
2. **整理快照**：只导出选定版本中允许公开的文件，不复制私密仓库的 `.git` 目录，不把私密开发分支直接推送到本仓库。
3. **审查内容**：检查源码、资源、配置样例、文档和生成文件，清除秘密、个人信息以及不打算公开的内容。不要以文件名或忽略规则代替内容审查。
4. **构建与验证**：尽量从整理后的公开快照完成干净构建和测试，检查资源、依赖及必要构建文件是否齐全。确认即将上传的 `.jar` 与该快照一致。
5. **提交公开版本**：在本仓库现有历史上新增一个版本提交，保留已有公开文档和反馈模板，并正确移除上一版中已不再发布的源码文件。
6. **发布版本**：公开 `main` 提交会自动生成开发预发布；正式稳定版仍需维护者核对源码、版本说明、附件与验收范围后，在对应提交上创建正式标签并确认发布。
7. **发布后复核**：检查源码、版本标签、下载文件、安装说明及链接是否相互对应。

私密提交与公开提交的对应关系可保存在私密开发环境中，不必在公开说明中暴露内部开发记录。

## 内容检查清单

- [ ] 已确认版本号、源提交和公开文件清单。
- [ ] 未包含私密 Git 历史、内部开发文档或未批准公开的实验内容。
- [ ] 未包含 API Key、访问令牌、密码、私钥或带凭据的服务地址。
- [ ] 未包含真实账号配置、私人聊天记录、运行日志、测试存档或其他个人信息。
- [ ] 配置样例仅使用占位值，没有硬编码真实凭据。
- [ ] 已检查源码、资源与 `.jar` 内部内容，不能只检查文件名。
- [ ] 公开快照包含必要的构建文件和可合法分发的资源。
- [ ] 已明确并补齐本版本的许可证、第三方声明及资源来源要求。
- [ ] 已从公开快照验证构建，并记录测试范围与已知问题。
- [ ] README 中的功能描述与本次实际发布能力一致。
- [ ] 已逐项核对 Minecraft、Java、加载器、依赖和安装配置要求。
- [ ] Release 附件、版本标签与公开源码快照对应。

## 不应采用的同步方式

不要将私密开发仓库的分支、所有标签或镜像直接推送到本仓库，也不要用复制 `.git` 的方式建立公开历史。发布目标是经过审查的文件快照，而不是内部开发记录。

`git archive` 可以导出指定树或提交的文件，但它不是自动脱敏工具；`export-ignore` 只负责排除匹配文件，不能代替公开文件清单与内容审查。详见 [Git 官方 git-archive 文档](https://git-scm.com/docs/git-archive)。

## Release 说明模板

以下是填写结构，不代表已经存在对应版本。发布前应替换所有占位内容。

```markdown
# DivZero <版本号>

## 支持环境
- Minecraft：<版本>
- Java：<版本>
- 加载器：<名称与版本>
- 必需依赖：<名称与版本，或无>
- 已验证的运行环境：<客户端、单人游戏、服务端等>

## 本次更新
<已实现并验证的新增功能、改进与修复>

## 安装与配置
<安装步骤、必要配置与升级注意事项>

## 已知问题
<当前限制、不兼容项与测试范围>

## 下载
<对应的 Mod .jar 文件名与附件说明>
```

## 已配置的自动开发预发布

公开 `main` 的成功构建自动生成独立 Pre-release，标题与正文标注 Mod 版本、支持的 Minecraft 版本、NeoForge 与 Java。只上传主 JAR、WebGUI 与各平台 MCEF 运行 JAR，不上传整合 ZIP、独立元数据／许可文本或开发源码 JAR；GitHub 自带的源码 ZIP/tar.gz 链接不是安装包。主 JAR 内含本项目许可，依赖保留原字节及许可证，固定对应源码与声明通过 Release 正文链接提供。校验值在正文，完整打包审计仍保留在 CI 工件。

发布只使用同次成功构建产物，先保留 draft、核验全部附件，再公开；独立标签包含版本、提交和运行身份，不 force 更新、不覆盖正式版本、不抢稳定版 Latest。PR 无 Release 写权限。构建测试不代表真实模型或完整游戏验收。

此流程不改变源码快照人工审查原则：私密开发中的日常提交不会自动公开，禁止直接同步其分支或历史。发布凭据只在发布 job 使用临时 `GITHUB_TOKEN`，不得写入源码、提交记录、公开文档或日志。
