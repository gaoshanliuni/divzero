# Forge 1.8.9 全量回移

**当前状态：前置工具与需求基线，尚无可运行的 1.8.9 DivZero JAR。不能作为已适配版本安装。**

目标实例为 Minecraft 1.8.9 / Forge 11.15.1.2318。用户在 2026-10-05 明确要求保留全部现有功能，并复刻新版物品、战斗机制及依赖能力；随后明确取消 KubeJS 的迁移。不缩减为 PvP 专版，不将新版独有功能简单隐藏。

`requirements.json` 保留 45 个迁移工作域，均待原生适配与验证。分域用于组织实现，不是全部子功能数量或完成率。必须结合现有源码、公开功能文档与运行时工具目录核对，不以这张表代替逐项验收。

## 已实现

- `tools/inventory.py` 扫描全部八个现有模块的 Java 源码，包括 Python 变体与带 Smoke/Fixture 名称的文件；记录相对路径、源文件摘要、平台依赖和静态工具声明位置。只输出源代码覆盖信息，不将共享源码当作移植完成。
- `tools/nbt.py` 有界读取 Java 版 NBT 与 Anvil 区块，校验坐标、格式、调色板及位压缩；不启动源世界。
- `tools/map_blueprint.py` 从带标记的 26.1.2 PvP 世界无损提取竞技场/大厅边界内的全部方块状态与空气，保留出生位置、保护边界所需几何和来源散列；不覆盖源存档或已有输出。
- `bridge/` 为独立 Java 8 协议库，使用版本化、有界的进程管道帧，携带世界、玩家、会话、操作和修订号。截断/未知协议/超长数据会终止该通信流，写入失败不在原流自动重试。它尚未接入 Forge 或既有 Worker，不能独立充当 Mod。
- 原地图提取边界为 `(-18,97,754)` 至 `(18,110,818)`，共 33,670 个位置。产物明确标记 `playable=false`。地图中的容器/方块实体、未知版本或损坏区块必须先实现明确迁移，不能静默丢弃。

这些工具不属于 Mod，不提供游戏中聊天、界面、战斗或新物品。蓝图不是旧版存档；尚未执行 1.8.9 Native/PvP 测试。

## 实现方向及约束

现有通用模块以 Java 25 编译，目标 Forge 的启动元数据要求 Java 8。拟保留通用服务在独立 Java 25 进程，通过有版本、世界/玩家身份、操作 ID 与回执的协议连接 Java 8 游戏适配层。需要实际完成服务组合与每个 Native 端口；直接把 Worker JAR 放到 mods 或修改元数据无法解决兼容。

游戏内每 Tick 的移动、瞄准、物理、伤害与紧急停止必须在目标游戏线程执行；服务进程、磁盘或模型不能阻塞 Tick。未收到执行回执不得报告完成，未知写入不得自动重放。网络两端需共同升级，服务端不能借本机桥获得客户端电脑权限。

LDLib2、渲染、实体、命令和网络接口均须旧版实现。上游 Modrinth 项目 `B1CBVXHX`（LDLib）在检查时未列出 1.8.9；其 LGPL 源码、修改与构建信息需要保留。必须按实际依赖版本进一步审查，不因有同名项目就声称可加载。**不回移或要求安装 KubeJS，不承诺兼容 KubeJS 专用 API。** DivZero 自身的动态界面和通用脚本能力保留在迁移清单中，须另接旧版原生实现；现有 Rhino 脚本执行与 KubeJS 平台绑定分别处理。

副手须实际保存、交换、显示、同步与使用。新版盾牌/弩/三叉戟/图腾/重锤/装备、冷却及伤害规则须共同回移，不能只注册外观、直接改血量或以 1.8 连点伤害冒充新版战斗。未知方块不得自动改成空气/石头；地图导入必须逐状态解析、写入、读回，通过后才能启用 PvP 标记。

现有 NeoForge 版本、用户存档/配置与两份未完成 PackageAssetSmoke 修改保持独立。只同步检查过的源码、工具和文档，不同步地图数据、凭据或运行产物。不自动创建 Release。

## 运行前置工具

在仓库根目录使用 Python 3.12+；本地 shell 通过 PowerShell 7 执行。

```text
python legacy189/tools/inventory.py --output build/legacy189/source-inventory.json
python legacy189/tools/map_blueprint.py --world <已关闭的原PvP存档> --output build/legacy189/pvp-arena-transfer.json
python -m unittest discover -s legacy189/tests -v
```

所有 Java 构建继续使用公开 main 的 GitHub Actions。前置工具测试通过只证明离线读取/提取；不能替代 Forge 启动、F2、双方真实伤害、现代物品、轮次结束、存档重进和双客户端联验。

公开 `Legacy 1.8.9 migration foundation` 工作流运行离线工具测试，并用 Java 25 编译 `--release 8` 的桥接协议，在真实 Java 8 子进程上验证管道通信。子进程是明确的测试用 echo peer，不是 Forge、模型 Provider 或实际通用服务。工作流不生成可玩的安装包、不发布 Release。
